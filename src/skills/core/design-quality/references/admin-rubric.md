# Admin / CRM review rubric

A deduplicated checklist for reviewing a CRM or admin web app. It is distilled
from the sources in `sources.md`.

Each row has three parts:

- **Rule**: a concrete threshold or behaviour.
- **Sources**: the keys below.
- **DOM?**: whether the rule can be checked from a rendered DOM snapshot
  (computed styles plus geometry), and how. `covered: <rule>` means
  `codeality-ui` already checks it.

## 1. Navigation and page frame

| #   | Rule                                                                                                                                                              | Sources                             | DOM?                                                                                                                                                                              |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| N1  | The current section is marked in the navigation with `aria-current="page"` and a visual difference other than colour alone (weight, indicator bar or background). | WCAG 1.4.1, NNG heuristic 1         | yes. Find the nav link whose `href` matches the route; assert `aria-current` is set and its computed style differs from its siblings in at least one property other than `color`. |
| N2  | The page `<h1>` (or title region) matches the active navigation label.                                                                                            | rubric 7, GOV question pages        | yes. Normalised text of `h1` against the text of the `aria-current` nav item.                                                                                                     |
| N3  | Exactly one `<main>` landmark, and a skip link as the first focusable element.                                                                                    | VWIG, KRE a11y, WCAG 2.4.1          | yes. Count `main`; the first element in tab order has an `href` starting with `#` that points to main.                                                                            |
| N4  | Filters, tabs, sort and pagination are reflected in the URL query, so a reload or a shared link restores the view.                                                | VWIG Navigation & State             | partial. Click a tab or filter and assert `location.search` changed. Needs interaction, not a static snapshot.                                                                    |
| N5  | Navigation items are real `<a href>` links (Cmd-click works), not `div` elements with `onclick`.                                                                  | VWIG, BUI                           | yes. Nav items with role link or a pointer cursor but `tagName != A` or no `href`.                                                                                                |
| N6  | The sidebar uses the same background as the canvas with a 1px border, not a contrasting block.                                                                    | ID                                  | yes. Compare the sidebar and main `backgroundColor`; flag a delta E above 5 together with no border. Advisory.                                                                    |
| N7  | Two navigation items do not share the same icon.                                                                                                                  | derived (TODO `duplicate-nav-icon`) | yes. Hash SVG `innerHTML` per nav item.                                                                                                                                           |
| N8  | Sticky headers do not cover focused or anchored content: `scroll-padding-top` is at least the header height.                                                      | WCAG 2.4.11, VWIG, UPM              | yes. Read the sticky header height and the computed `scroll-padding-top` on the scroller.                                                                                         |

## 2. Lists and data tables

| #   | Rule                                                                                                                                                       | Sources                                                                       | DOM?                                                                                                                                                                                    |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| L1  | Repeated records render as `<table>` (or `role=grid`) with `<th scope>` headers when they have three or more comparable fields, never as a stack of cards. | GOV table, OFP ("dense but organised"), OFS (no app UI of stacked cards), NNG | yes. Sibling groups of N or more same-signature elements, each with three or more text leaves, outside a table or grid.                                                                 |
| L2  | Column cells align on one x per column.                                                                                                                    | RUI, KRE                                                                      | covered: `row-misaligned`                                                                                                                                                               |
| L3  | Numbers, money, dates and times are right-aligned (trailing edge) with `font-variant-numeric: tabular-nums`.                                               | KRE layout, VWIG typography, BUI, ID                                          | yes. Cells whose text matches a numeric or date pattern: check `text-align` and the cell's x end against its column, and check `fontVariantNumeric` contains `tabular-nums`.            |
| L4  | The header row is the same height as body rows, and row height comes from one scale: 24, 32, 40, 48 or 64px.                                               | CDS                                                                           | yes. Collect `tr` heights; all body rows have one height (plus or minus 1px) and it is on the scale.                                                                                    |
| L5  | The first column is a human-readable identifier (name or subject), not a database ID or UUID.                                                              | NNG                                                                           | yes. The first column's text matches `^[0-9a-f-]{8,}$` or `^#?\d+$` in most rows.                                                                                                       |
| L6  | A list over 50 rows has pagination, "load more" or virtualisation, and shows a total count.                                                                | VWIG performance, CDS pagination, rubric 7                                    | yes. Row count above 50 and no `nav[aria-label*=pagination]`, no button matching /more\|next/i, and no node with `content-visibility: auto`. TODO `oversized-list` covers part of this. |
| L7  | Pagination sits at the bottom of the table.                                                                                                                | CDS                                                                           | yes. The pagination control's y is greater than the last row's y.                                                                                                                       |
| L8  | One or two row actions appear inline with labels; three or more become a row menu plus checkbox batch actions with select-all.                             | NNG data tables, CDS batch actions                                            | yes. Count buttons per row; if three or more and no `[role=checkbox]` or `input[type=checkbox]` in the header row, flag.                                                                |
| L9  | When the row is the click target, the whole row is clickable and shows a hover state.                                                                      | rubric 6                                                                      | partial. Hover a row with a link in its first cell and diff computed `backgroundColor` before and after.                                                                                |
| L10 | An active filter is visible on the closed filter control (count or chip), with one action that clears all.                                                 | CDS filtering, NNG                                                            | partial. Needs a filter applied by interaction.                                                                                                                                         |
| L11 | A column title wraps to at most two lines, then truncates with an ellipsis and a tooltip.                                                                  | CDS                                                                           | yes. `th` with a rendered line count above 2 (height / lineHeight), or a clip without `textOverflow: ellipsis` (covered by `text-clipped`).                                             |
| L12 | A large table freezes its header (and its first column when it scrolls horizontally).                                                                      | NNG                                                                           | yes. A table taller than the viewport whose `thead th` is not `position: sticky`.                                                                                                       |
| L13 | Truncated cell text keeps the start, shows an ellipsis and exposes the full text through `title`, a tooltip or the detail view.                            | VWIG content, CDS, rubric 8                                                   | yes. Covered for clipping (`text-clipped`, `text-hard-cut`); add a check for `title` or `aria-label` on ellipsised cells.                                                               |

## 4. Forms

| #   | Rule                                                                                                                                                          | Sources                                  | DOM?                                                                                                                                                            |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1  | Every control has a visible label above or beside it. A placeholder never replaces the label.                                                                 | GOV text input, VWIG, WCAG 3.3.2, UPM    | yes. axe `label` covers the accessible name. | F2  | Labels have no trailing colon and use sentence case. Label text matches `:\s*$` or contains `*`.                                                                                                                |
| F3  | Input width fits the expected content: postcode, phone, date and amount inputs are not full width.                                                            | GOV text input                           | yes. Inputs whose `autocomplete` or `type` is `postal-code`, `tel`, `bday` or `number` and whose width is above 60% of the form column.                         |
| F4  | Correct `type`, `inputmode` and `autocomplete` on email, phone, URL, name and address fields.                                                                 | VWIG forms, KRE a11y forms               | yes. | F5  | Paste is never blocked.                                                                                                                                       | VWIG, BUI, WCAG 3.3.8                    | partial. | F6  | Errors appear inline, below the field, linked through `aria-describedby`, plus an error summary at the top that takes focus on submit. | F7  | Error text names the field and the fix ("Enter how many hours you work a week"), not "Invalid input".                                                         | GOV, VWIG copy                           | partial. Text pattern check after submit.                                                                                                                       |
| F8  | The submit button stays enabled until the request starts, then shows a spinner and "Saving…".                                                                 | VWIG forms                               | partial                                                                                                                                                         |
| F9  | Leaving with unsaved changes warns (`beforeunload` or a router guard).                                                                                        | VWIG                                     | partial                                                                                                                                                         |
| F10 | Mobile inputs are at least 16px, so iOS does not zoom.                                                                                                        | KRE typography, UPM                      | yes. Computed `fontSize` of inputs at a 390px viewport.                                                                                                         |
| F11 | Gap between groups is at least 2x the gap within a group (label to input 4-8px, field to field 16-24px).                                                      | KRE grouping, Laws of UX proximity       | yes. | F12 | Checkbox and radio: label and control share one hit target with no dead zone.                                                                                 | VWIG                                     | yes. ## 5. Inbox, chat and email threads

| #   | Rule                                                                                                                                            | Sources                                                | DOM?                                                                                                                       |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| T1  | Each conversation row shows who, a preview, when and status (unread or channel) in one line or two fixed lines, with every row the same height. | rubric 4, CDS rows                                     | yes. Row height variance; presence of a time element per row.                                                              |
| T2  | Unread is shown by weight or a dot plus text or `aria-label`, not colour alone.                                                                 | WCAG 1.4.1, UPM                                        | partial. | T3  | Times are relative when recent ("5 min") and absolute on hover (`<time datetime>` with a `title`), formatted through `Intl`.                    | rubric 8, VWIG locale                                  | yes. | T4  | Message bubbles cap their width at about 65-75ch; long tokens (URLs, IDs) wrap with `overflow-wrap: anywhere`.                                  | KRE measure, UPM long-token wrapping                   | yes. | T5  | URLs in messages are links.                                                                                                                     | derived                                                | covered: `bare-url`                                                                                                        |
| T6  | Unsupported or empty payloads get a designed state, not "[media message]".                                                                      | rubric 8                                               | covered: `raw-placeholder`                                                                                                 |
| T7  | The composer stays pinned and visible, and its action row never scrolls away inside a scrolling thread.                                         | KRE "clipping", OFP stable dimensions                  | yes. | T8  | A long thread scrolls inside a fixed-height pane, not the whole page.                                                                           | G5 ("fixed height containers with internal scrolling") | yes. Page `scrollHeight` above 3x the viewport while a thread container exists without `overflow-y: auto`.                 |
| T9  | Live updates are announced through `aria-live="polite"` and a new message does not steal focus.                                                 | VWIG, KRE screen readers                               | yes. ## 8. Density, layout and spacing

| #   | Rule                                                                                                                                     | Sources                                            | DOM?                                                                                                |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| P1  | All padding, margins and gaps are multiples of 4px.                                                                                      | G5, M3 (4dp baseline), ID, BUI                     | yes. Computed paddings and gaps that are not multiples of 4 (allowing 1-2px borders and hairlines). |
| P2  | Spacing has rhythm: more than three distinct gap values, and the gap above a heading is larger than the gap below it.                    | IMP `monotonous-spacing` and `heading-rhythm`, KRE | yes. Each heading's top gap against its bottom gap.                                                 |
| P3  | Bordered controls sit 12px apart; borderless icon buttons have 24px of clearance; hit areas never overlap.                               | KRE spacing                                        | yes. Bounding-box gaps between sibling controls.                                                    |
| P4  | Padding is symmetrical inside a container unless content demands otherwise.                                                              | ID                                                 | yes. `paddingLeft` against `paddingRight` (and top against bottom) on cards and buttons.            |
| P5  | Text inside a bordered or filled container has at least 8px (ideally 12-16px) inset.                                                     | IMP `cramped-padding`, KRE                         | covered for inputs (`control-inset`); extend to text containers.                                    |
| P6  | Body text never touches the viewport edge: at least 16px gutter on mobile.                                                               | IMP `body-text-viewport-edge`, KRE                 | yes                                                                                                 |
| P7  | The data screen uses the available width; reading text keeps a 65-75ch measure.                                                          | RUI, rubric 3, IMP `line-length`                   | covered: `content-width`; add a line-length check.                                                  |
| P8  | One radius scale (for example 4/8/12), with card radius at most 8px in admin UI, and nested radius concentric (outer = inner + padding). | OFP, KRE better-ui, ID                             | yes. Distinct radius values; child radius against parent radius minus padding.                      |
| P9  | One depth strategy: borders, shadows or tint shifts, not a border plus a wide shadow on the same element.                                | ID, IMP `gpt-thin-border-wide-shadow`              | yes. TODO `ghost-elevation`.                                                                        |
| P10 | Fixed-format controls (icon buttons, counters, toolbars) have stable dimensions; hover or loading text does not resize them.             | OFP                                                | partial. | P11 | One z-index scale, no arbitrary values.                                                                                                  | BUI, UPM                                           | yes. Distinct computed `z-index` values above 0; more than six distinct values is a smell.          |
| P12 | Fixed or floating elements never overlap text or controls.                                                                               | OFP, OFS, IMP `text-occlusion`                     | yes. Intersect the boxes of fixed and sticky elements with text boxes.                              |
